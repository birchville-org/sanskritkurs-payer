    Aufbau des Moduls (per EDIT-01, EDIT-03, EDIT-04):

    Imports (alle mit pinned Versionen):
    - import markdownit from 'https://esm.sh/markdown-it@14.2.0'
    - import container from 'https://esm.sh/markdown-it-container@4.0.0'
    - import multimd from 'https://esm.sh/markdown-it-multimd-table@4.2.3'

    buildRenderer() erstellt eine md-Instanz mit: html: true, breaks: true, linkify: false.

    Registrierungsreihenfolge (identisch zu config.mjs, Pitfall 2 beachten):
    1. md.core.ruler.before('normalize', 'prevent_br_link', state => { state.src = state.src.replace(/\[\[br\]\]\(/g, '[[br]] ('); }) — spiegelt config.mjs Zeile 223-225
    2. md.use(multimd, { multiline: true, rowspan: true, headerless: true, multiscript: true, colspans: true }) — spiegelt config.mjs Zeilen 226-232
    3. Schleife über CONTAINERS-Array (alle 12 Namen in Reihenfolge aus config.mjs):
       ['grammar-box', 'grammar-box2', 'media', 'center', 'metrik-schema', 'important',
        'deleteme-box', 'note-box', 'laut-table', 'indent', 'compact', 'no-header']
       Jeder Container: render gibt bei nesting === 1 `<div class="${name} custom-block">\n`
       zurück, sonst `</div>\n` — identisch zu config.mjs.
    4. scholarly_fixes als md.core.ruler.after('linkify', ...) analog zu config.mjs:
       - Iteriert state.tokens, sucht type === 'inline'
       - Bei child.type === 'text': splittet auf '[[br]]' (EDIT-03)
       - Pro Segment: spaltet auf /(⟪[ऀ-ॿ]+⟫|[ऀ-ॿ]+|\[\[indent\]\])/g
       - ⟨text⟩ (U+27EA/U+27EB) → span.sanskrit-dev (Wrapper entfernen)
       - Bare Devanāgarī → span.sanskrit-dev (kein hindi-dev, Editor kennt keine Locale)
       - [[indent]] → span.indent-inline
       - Zwischen [[br]]-Segmenten: hardbreak-Token einfügen

    buildRenderer() gibt das konfigurierte md-Objekt zurück.

    Am Ende des Modul-Blocks: window.buildRenderer = buildRenderer;

    Sicherheitshinweis (per RESEARCH.md Security Domain): html: true ist für dieses
    Single-Author-Werkzeug akzeptabel. Kommentar im Code: "html: true — intentional for
    author-only preview tool; mirrors VitePress internal default (see RESEARCH.md A1)".

    NICHT tun: keinen separaten editor-renderer.js erstellen — alles bleibt in
    qa_viewer.html (per RESEARCH.md Architecture Patterns "no new files required").
